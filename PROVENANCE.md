# Provenance

This repository is a source export of the bekiper analysis engine from the
private development repository.

- Source revision: `eca10e0e17cac9fb1666ffc9ef046897f6eaa3ad`
- Export tool: `release/public/export.sh` (private repository)

## What differs from the source revision

Every file is byte-identical to the source revision except:

| File | Change |
|---|---|
| `simit.toml`, `.github/workflows/nix-builds.yaml` | Added: Simit-generated hosted-runner Nix builds of the public packages |
| `LICENSE`, `README.md`, `COMMERCIAL.md`, `CONTRIBUTING.md`, `CITATION.cff`, `.zenodo.json`, `PROVENANCE.md` | Added for the public release |
| `Cargo.toml`, `**/pyproject.toml` | `license` field set to `AGPL-3.0-only` |
| `deny.toml` | `AGPL-3.0-only` added to the allowed licenses |
| `rust/bekiper-cli/Cargo.toml` | Removed the `gui` and `annotate-*` features and the optional `bekiper-annotate` dependency (annotation UI is not part of this release) |
| `rust/bekiper-ingress/build.rs` | Dropped the registry source from the preparation cache key (`BEKIPER_PREPARATION_VERSION`); not part of the engine identity |
| `.cargo/config.toml` | Sets `BEKIPER_SOURCE_CARGO_LOCK` (below) |
| `Cargo.lock` | Regenerated by Cargo for the exported workspace members |
| `Cargo.lock.source` | The source revision's original `Cargo.lock`, unmodified |
| `flake.nix`, `flake.lock`, `nix/` | Reduced to the exported packages and dev shell |

## Engine identity

`bekiper-post-analysis` embeds a SHA-256 digest of its own sources, the
`bekiper-math` and `bekiper-feature` sources, their manifests, its build script
and the source workspace lock (`Cargo.lock.source`). None of these files is
changed by the export, so a build of this repository embeds the same
`source_sha256` that is recorded in `run_manifest.json` (`code.source_sha256`)
of every post-analysis run produced at the source revision.

To check a published run against your build:

```sh
bekiper-post-analysis verify --input <run>/data/_post_analysis/<cohort-id>
```

The output contains `code` (identity recorded in the run) and `verifier_code`
(identity of the binary you built). Their `source_sha256` and
`source_lock_sha256` values must be equal.
